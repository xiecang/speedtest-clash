# V2 格式、测量与探针契约

## 转换

`Decode` 按结构识别 Clash YAML、sing-box JSON、URI 和 Base64 URI 订阅；单来源及其provider合计最多16MiB、5万规范节点，provider 递归最多8层，来源全部读取解析成功后才发出有界批次。`LoadSource` 支持文件、HTTP(S) 和 `inline:`。未知字段保存在规范节点中，同格式导出保留；跨格式不支持的字段返回诊断，不能静默丢失。`Convert` 保留严格整批接口；`LoadSourceDetailed` / `LoadSourcesDetailed` 记录独立坏条目及依赖排除诊断，保留可用条目，单个 provider 文档失败只回退该文档，继续其他 provider；主文档损坏则拒绝该来源。多来源入口保持顺序，合并去重及依赖解析后分批发送。

Clash 保留 cvt 全部18种类型：HTTP、SOCKS5、SS、SSR、Mieru、Snell、VMess、VLESS、Trojan、Hysteria/Hysteria2、TUIC、AnyTLS、WireGuard、SSH、Sudoku、Masque、TrustTunnel。URI支持其中除Snell/SSH/Sudoku/Masque/TrustTunnel外的13种，兼容hy/hy2/trojan-go/mieru/socks5+tls别名，未知或重复连接参数明确诊断。HTTPUpgrade/XHTTP/Reality/ECH/端口及插件字段按目标能力保留或拒绝。sing-box 原生格式还可保留其其他协议，是否可测由构建与原生校验决定。反向转换仅支持显式映射的字段；插件、复杂传输及 URI 无法表达的链路/参数会拒绝对应输出。WireGuard 使用1.14 endpoints，禁止测试中启用 system 模式。TLS验证默认开启，显式 insecure 才会保留。

`LoadSourcesDetailed(ctx, []SourceRequest, client, emit)` 提供逐源 UserAgent、Proxy、AllowLocalFiles（默认false，嵌套provider也生效）。支持HTTP/HTTPS/SOCKS5/SOCKS5h代理、Data URL、empty；SourceSummary.Sources按输入顺序包含来源Index、错误、允许转发的Headers和实际读取Bytes。最多64来源、总输入16MiB、总条目50,000（包括坏条目）、规范暂存64MiB，失败文档回滚暂存；嵌套 provider 失败时设置 `SourceSummary.Partial`（JSON `partial`），即使诊断数量达上限也保留此标记。有效节点完成依赖解析后正常发出；部分失败且无有效节点返回普通错误，只有完整空来源才返回 `ErrNoNodes`。取消、暂存 I/O 和全局预算错误终止整次调用，回调错误原样返回。旧单来源接口显式允许本地文件以保持兼容。

NodeKey 是规范配置与依赖路径哈希，不含名称、hidden、日期和测速指标；源格式参与身份，不承诺不同源格式自动合并。缺失依赖、同名歧义、循环均拒绝。导出名称使用稳定 NodeKey，便于规则及依赖引用。

`ConvertRule` 支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、AND/OR/NOT、NETWORK、单个源/目标端口、IP-CIDR(6)、SRC-IP-CIDR、PROCESS-NAME/PATH、RULE-SET 及 MATCH；需要相应内核资源才能发布 RULE-SET。未知语法返回错误，GEOIP/GEOSITE 使用对应远程原生规则集，范围语法不近似转换。`RewriteRuleTarget` 仅替换外层目标，保留嵌套语法及 no-resolve。

## 测量

所有可访问候选执行下载：50MiB总预算分给5条流，15s采样窗口；一个 Budget 内同一时刻仅一个节点测带宽。正常结束记录 `budget` 或 `window`；提前EOF、短读、重置和异常超时记录 `error`，部分成功不能覆盖失败。指标记录健康请求分母、冷/复用成功耗时中位数、下载响应头完成中位数、实际字节及耗时；删除尾分位数和伪抖动。有效吞吐以字节/秒保存，`rate_limited=true` 表示实际等待本地额度。完整定义见 [METRICS.md](METRICS.md)。

可访问性默认10并发。AI5（可配10），最多前20个通用合格候选；每节点H1 SSE、实际协商H2 SSE、WebSocket并行，完整180s主动输出→计划空闲→恢复→结束标记。逐序号校验；主动阶段10s无进展或无结束标记失败。受控协议不消费模型token；缓冲会影响真实延迟指标，不把收到计划空闲标记时的本地时钟估计误当故障。双内核需顺序调用/由xcproxy worker调度。

实际通用阶段、AI阶段、服务检测、IP查询分别记录测量时间。`pass/fail/unknown`与`metric_version:2`（排序策略另由调用方维护）独立；报告含NodeKey、节点配置与测量计划哈希、worker环境、内核版本、开始/结束时间、失败分类、原始指标、缓存及限速信息。改探针或检测时长后，旧计划结果必须重新检测。

探针不可用、控制检查失败、繁忙记为基础设施unknown；节点失败会再次执行直连控制，避免大面积误隔离。未配置服务/IP返回unknown。OpenAI、Claude、Gemini分别记录HTTP可用性，2h有效；不保证登录后的产品可用。

## IP信誉

始终通过被测节点查询实际出口；IP、地址族、提供方名称、URL及检查版本作为7天缓存键。支持提供方URL中的 `{ip}` 和扁平JSON：ip/query、country_code/country（两位代码）、asn/as/org、network_type、reputation（0..100高分较好）、confidence（0..1）。不假称已经实现 OpenStats 的所有站点抓取器；不同提供方可通过返回该规范的适配端接入。出口冲突、限流、超时、未配置都未知；机房IP不硬淘汰。xcproxy把有效信誉放在质量指标之后、稳定键之前作软排序，未知以50中性值处理。

## HTTP与嵌入

独立 `Handler` 使用 Bearer `ProbeToken`，提供 POST `/api/v2/convert`、POST `/api/v2/evaluate`、GET `/api/v2/capabilities` 及 `/api/v2/probe/*`。JSON时长以纳秒整数；YAML配置用 `180s`。转换接口直接发送源文本，目标由 `?format=clash-yaml|sing-box-json|uri` 指定；evaluate发送 `{schema_version:2,nodes:[...]}`，使用server配置的检测计划。独立Handler同时最多2个Evaluate批次，共享Budget。

探针路径：health、download、sse、ws；默认最多128活跃流会话，下载单请求最多256MiB，认证常量时间比较。序号、idle时段及done由服务端生成，客户端验证；无压缩缓冲。嵌入服务器须设置请求BaseContext并在关闭时取消它，代理需允许Flush/HTTP2/WebSocket与超过180s的连接，不配置短WriteTimeout。public listener须设置token；保持token在环境变量/受保护配置，不写报告。

## 验证边界

默认 `make test` 包含加速的完整协议/异常/生命周期测试。真实180s矩阵：`NQ_AI_LONG_TEST=1 go test -tags 'with_quic,with_utls,with_wireguard,with_gvisor,with_clash_api' -run TestAIParallelLongRun -v -timeout 20m`。本机loopback结果不等于公网节点或ChatGPT桌面TUN验收；真实节点影子评估与部署切换仍需另行执行。


Hysteria2 的 URI userinfo 作为完整认证串保留。用户名与密码访问器已经 URL 解码，规范化不再额外解码；`name:secret` 与 `name%3Asecret` 均得到 `name:secret`，`%253A` 保留为字面 `%3A`。编码继续对整个认证串转义。


## 2026-10-12 离线 V1 解析核对

使用归档 V1 的 `ProxySourceLoader.Load` 和锁定的 Mihomo 1.19.24 读取 176 份冻结响应；当前详细入口使用同一批响应并禁用 HTTP transport。真实样本不含 proxy-providers，provider 的正常、损坏、循环、超时及后续成功内容由本地 httptest 固定提供，不访问订阅网络或执行节点测速。

# Failure attribution

V2 reports may include `failure_origin` and `general_failure_origin` with values `node`, `environment`, `probe`, or `unknown`. Only a verified peer/configuration error is a node failure; the currently verified native case is `node_auth_required` for a SOCKS5 peer that requires authentication absent from the node configuration. Worker resource or route errors, cancelled work, probe failures, and unattributed transport errors use `unknown` status with their corresponding origin. Older reports without origin remain valid diagnostic records and are not proof that a node failed.
